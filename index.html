Enhancement Narratives

Software Design and Engineering

Description

The original artifact used for the "software engineering and design" artifact is Project One from a course, CS-320: Software Testing, Automation, and Quality Assurance. The original purpose of the artifact was to demonstrate knowledge of how to implement service classes and test them with JUnit.

Justification

I chose this artifact because I knew that I could convert it to another programming language 1:1 including tests by using C++. It also provided a clean base to add functionality to. This allowed me to implement a singleton design pattern on each of the service classes. It also let me remove bad functionality from bad coding, which was validating input inside the model class, and move it into its own module. This enhancement showed how much I had improved since CS-320 by making a more sophisticated program, but not necessarily more complex.

Reflection

The only real challenges faced when creating this enhancement came from using Visual Studio and Google Test in combination which gave a significant hangup due to a misconfiguration. Time could be considered an issue as if I had more time, I would have fully implemented the dynamic testing menu instead of restricting it to one class. Each of the course outcomes that were laid out in the enhancement plan were met other than #2 which was partially met. I started creating non-code commented documentation but ultimately felt it wasn't necessary due to the program not being complex enough to warrant it.

Algorithms and Data Structures

Description

The original artifact used for the "algorithm and data structures" enhancement is the Binary Search Tree (BST) assignment from CS-300: Data Structures and Algorithms. The original purpose of this program was to create objects from a CSV file and load them into a BST. The program contained functionality to insert, remove, search, and print via in order traversal.

Justification

This artifact was selected for enhancement due to having a clear, demonstratable upgrade path meaning that the next logical step for a BST is to either go for an AVL Tree or a Red-Black Tree. Of the two ways to balance a BST, I chose the AVL Tree route due to this being a read-heavy data structure that is loaded with data once and then has functions performed on it. This enhancement allowed for demonstration of improving the time complexity of a data structure without changing its underlying functionality of being a BST. The project also allowed for further use of the C++ Google Test library.

Reflection

As with the software engineering enhancement, issues persisted with misconfigurations in Visual Studio and the Google Test package. The artifact was improved in time complexity to O(log n) in most cases (for insert, removal, and search operations) where the unbalanced BST can devolve into a linked list at O(n). The artifact enhancement also refactored out the BST class to be generic, same with the AVL Tree class and functions associated with the original artifact were also refactored into their own class. Each of the course outcomes were met other than #2 as I felt no need to go into detailed documentation for a smaller, straight-forward project.

Databases

Description

The original artifact used for this enhancement is an open-source project from FreeCodeCamp which is a customer management Android application that is used as a showcase for SQLite. The original artifact is written in Java using the Gradle build tool. The project uses a minimum Android SDK of 24 and target SDK of 35.

Justification

The purpose for inclusion of this artifact into my ePortfolio came down to a lack of options for SNHU related database projects as most of them were done within VM's that I lack control over. The artifact also has endless enhancement opportunities due to its basic nature. The enhancements allowed me to display skills in SQLite using regular and virtual tables with FTS4. It also allowed me to use logging throughout the program as well as exception handling. Lastly, the original artifact gave opportunity to refactor original activity functionality into fragments that are managed by a bottom navigation menu. The enhancement improved the artifact by implementing a search fragment that gives the user ability to use full text searching (FTS) on customer data stored in SQL tables.

Reflection

There weren't any challenges faced for this artifact enhancement, and it was implemented as planned. I did learn a bit about how virtual tables work as an interface for the full-text search implementation and that the virtual table can be updated simultaneously with the normal database table using the same exact CRUD methods. It also made me more comfortable in converting activities to fragments and implementing fragments within an Android project. Each of the course outcomes that the enhancement aligns with were met other than outcome #2 which was an expectation of increased documentation. In this case, additional documentation could have been produced.
